# Labradorite

Labradorite 为 AI 角色提供可追溯的长期记忆。AI 通过 **stdio MCP** 保存原始材料、整理经历和检索往事；用户可以在浏览器里查看这些记录、照片和视频，以及每段经历所依据的原文。

例如，角色看了一段视频的前两分钟。上层 AI 可以保存视频、报告实际观看区间，再把自己的理解整理成一条经历。以后问起这件事时，AI 可以找到当时的记录，查看原视频和后续更正。视觉理解与经历整理由上层模型完成，Labradorite 负责保存、关联和检索。

## 从源码接入

准备 Node.js 24 或更高版本、[Vite+](https://viteplus.dev/) 的 `vp` 命令，以及支持 stdio MCP 的客户端。在仓库根目录运行：

```sh
vp i --frozen-lockfile
vpr build
vpr setup
```

首次在终端运行 `setup` 时可以进行 embedding 配置：

- **内置 Qwen**：自动下载并配置 llama.cpp 和 Qwen3-Embedding-0.6B Q8_0（总共约 650 MB）
- **手动配置 embedding**：填写已有服务的完整接口地址和模型名，或选择自己的 GGUF 文件
- **仅全文检索**：直接生成配置，使用本地关键词检索

完成后将 MCP 配置添加到 MCP 客户端：

1. 按 setup 输出的路径打开 `mcp.json`，将其中的 `Labradorite` 条目复制到 MCP 客户端配置中，然后重新加载客户端。
2. 让 AI 调用 `memory_status` 确认已连接。启用语义检索后，服务会在回顾保存成功或空闲时自动建立索引。

使用 AI 协助配置、自选数据目录或使用非交互方式部署，请查看[安装配置说明](docs/setup.md)。调整已安装服务的参数，请查看[运行时设置](docs/settings.md)。

## 浏览记忆库

服务默认启动 Web 查看器。点击「打开记忆库」即可浏览经历、人物和相册，在「回顾记录」里可以核对或撤销模型保存的修改。切换记忆库、找回登录链接和远程访问的步骤见 [Web 查看器使用指南](docs/webview.md)。

## 材料、经历与检索

| 操作           | MCP 工具                                                  | 行为                                                                                   |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 保存与展开     | `memory_submit`、`memory_read`                            | 保存原文、来源及覆盖范围，按 ID 展开。原始记录有误时可提交更正并关联旧材料。           |
| 整理与修订     | `memory_review`、`memory_amend`                           | 把材料组织为有来源依据的经历，预览差异，保留历次修订。                                 |
| 人物档案       | `memory_people`、`memory_review`、`memory_read`           | 按姓名或身份线索查找人物，查看当前印象、形成时间和依据的经历版本。                     |
| 角色与世界设定 | `memory_settings`、`memory_review`                        | 对话开始时读取生效设定，回顾时依据经历提出变化。主人可在查看器中确认、审阅和单独撤销。 |
| 查找记忆       | `memory_recall`                                           | 返回简短片段、命中原因和来源 ID，可按时间、渠道或生活线筛选。                          |
| 管理相册       | `memory_import_media`、`memory_album`                     | 从入口目录归档照片和受支持的 MP4，按当前空间与世界浏览。                               |
| 检查与删除     | `memory_status`、`memory_preview_delete`、`memory_delete` | 查看整理进度；删除前先查看受影响的材料、更正链和经历修订。                             |

启用语义检索后，可在项目目录运行以下命令，将路径替换为 setup 输出的运行配置路径：

```sh
vp run index "/path/to/runtime.json"
```

命令逐批处理至没有待索引片段，显示已完成数量、覆盖率及 UTC 当日请求用量。Ctrl+C 会等待当前批次结束并保存，然后停止；再次运行同一命令会跳过已完成片段。网络失败或额度耗尽时停止并说明原因，不自动重试。新增材料、修订经历或切换模型后，再次运行即可处理待索引内容。强制关闭进程后最多等待 30 秒再运行；CLI 与 MCP 不会同时处理同一作用域、同一模型的索引任务。

模型先用 `memory_recall`、`memory_read` 读取材料，然后用 `memory_review` 提交整理结果。保存成功后，后台会处理待索引片段。没有新经历要写时，调用 `memory_review({})` 即可结束回顾。最多等待索引 1 秒，仍在运行时返回 `indexing.state: "running"`。索引会在后台继续，可通过 `memory_status` 查看进度和结果。

服务启动或最近一次 MCP 工具调用结束后，连续空闲 **120 分钟**也会自动索引。在查看器的“设置”页可以调整空闲时长和每日请求上限，保存后重启 MCP 服务即可生效。

建索引会把材料片段发送到所配置的服务，混合检索也可能发送查询文本。仅全文检索和内置 llama.cpp 都在本机处理记忆。[配置示例和每日请求预算](docs/settings.md#embedding-配置与请求预算)

整理经历时，上层 AI 可以为经常出现或对角色有重要意义的人建档。先用 `memory_people` 检查姓名和身份线索。调用 `memory_review` 时，用 `source_ids` 引用原始材料，加上 `person_review` 即可在保存经历的同时建立或更新档案。只关联经历时省略 `impression`。如果新认识也依据更早的经历，在 `other_episodes` 中列出相应 ID 和版本。

空闲回顾时，上层 AI 可以用同一个 `memory_review`，通过 `episodes` 引用已存经历的 ID 和版本，写下完整的当前印象。例如“讨论复杂方案时，小林倾向先看草稿”。两种用法都默认直接保存。需要先预览时，加上 `dry_run: true` 即可。浏览器的“人物档案”和 `memory_read` 的 `kind: "person"` 都能查看历次判断，追溯到每次判断所依据的经历版本。

经历可通过 `happen` 单独保存事件发生时间、精度和来源依据，`review` 始终表示本次整理时间。补录旧事或再次提及时，修订省略 `happen` 会保留原值；无法确定的发生时间保持未知。`memory_recall` 使用 `time_basis: "happen"` 配合 `from` / `to` 查询发生时间，查看器的经历页也支持时间筛选与排序。字段及区间语义见[工具参考](docs/tools.md#事件发生时间)。

工具字段、检索返回值和媒体导入示例见[工具参考](docs/tools.md)。

## 备份、导出与恢复

支持完整备份记忆库及媒体文件，也可导出 Markdown，用其他编辑器浏览。搬迁或恢复服务时使用完整备份；Markdown 导出仅供阅读。具体命令见[备份、导出与恢复说明](docs/backup.md)。

## 开发

项目使用 TypeScript、Vite+、pnpm、Oxc 和 Vitest。在根目录运行 `vpr check`，可检查生成契约、格式和类型，并完成构建与测试。

模块职责、进程关系和存储数据流见[项目结构设计](docs/architecture.md)。
